# AI Resume Creator

Natural-language resume builder powered by the Anthropic Claude Messages API. Describe the role you want, answer the AI's follow-up questions, review and edit the generated resume, switch templates, download a text-based A4 PDF, and inspect the API usage generated by this app.

- Frontend: plain HTML, CSS, vanilla JavaScript (no framework)
- Backend: Node.js + Express, dotenv, express-rate-limit, puppeteer-core (PDF)
- AI: Anthropic Messages API via `fetch` (no SDK), isolated in `backend/src/services/anthropic.service.js`
- Storage: drafts live in the browser's `localStorage`; usage metadata in `backend/data/usage.jsonl`. No database.

## Setup

Requirements: Node.js 18+ and Google Chrome or Microsoft Edge (used headlessly for PDF export).

```bash
cd backend
npm install
cp .env.example .env      # Windows PowerShell: Copy-Item .env.example .env
# edit .env and set AI_API_KEY
npm start
```

Open http://localhost:3000.

If Chrome/Edge is installed in a non-standard location, set `CHROME_PATH` in `backend/.env`.

## Environment variables (`backend/.env`)

| Variable | Purpose |
|---|---|
| `PORT`, `NODE_ENV` | Server settings |
| `AI_PROVIDER` | Must be `anthropic` |
| `AI_API_KEY` | Key for resume-generation requests (server side only) |
| `AI_BASE_URL` | Anthropic API base, default `https://api.anthropic.com/v1` |
| `AI_MODEL` | Claude model used for every request |
| `AI_TIMEOUT_MS` | Per-request timeout |
| `AI_MAX_TOKENS` | Base output-token limit (see note below) |
| `AI_TEMPERATURE` | Optional; omitted from requests when blank |
| `AI_USAGE_API_ENABLED` | `true` enables Anthropic organization usage reporting |
| `AI_USAGE_API_KEY` | Separate, optional **Admin API** key (`sk-ant-admin...`). Not needed for resume generation |
| `AI_USAGE_BASE_URL`, `AI_USAGE_SCOPE` | Admin API base URL and the scope label shown in the dashboard |
| `USAGE_LOCALHOST_ONLY` | `true` restricts `/api/usage/*` to localhost |
| `AI_CREDIT_TOTAL`, `AI_CREDIT_START` | Optional; used for a labelled *estimated* remaining credit |
| `CHROME_PATH` | Optional path to Chrome/Edge for PDF export |

Note on `AI_MAX_TOKENS`: a full structured resume does not fit in 1024 tokens, so each AI operation uses `max(AI_MAX_TOKENS, floor)` where the floor is 2048-4096 depending on the feature (generation is 4096). Raise `AI_MAX_TOKENS` if you see a "response was cut off" error. Truncated responses are always reported as errors, never used.

`.env` is git-ignored. Never commit it.

## How it works

1. **Interview** (`POST /api/ai/interview`): you chat in plain language. Claude returns a reply with the next small group of questions plus the full structured resume built **only from facts you stated**.
2. **Generate** (`POST /api/ai/generate-resume`): Claude writes the summary, organizes skills and polishes bullets without adding facts. Output is parsed and validated server-side (`validators/common.js`); malformed, empty or truncated output is an error.
3. **Edit**: every section is editable (add/remove/reorder entries, bullets and sections, rename headings, hide sections, undo). Per-section AI actions (improve, concise, tailor, grammar, explain...) send only that section and show a before/after you can accept or reject.
4. **Job & Tips**: job-description analysis (required/preferred skills, gaps vs. your confirmed profile) and improvement suggestions.
5. **Templates**: Classic Professional, Modern Minimal, ATS-Friendly, Technical. Switching never changes content.
6. **PDF** (`POST /api/resume/pdf`): the exact preview HTML and `frontend/css/resume-preview.css` are rendered by headless Chrome/Edge, producing a selectable-text, multi-page A4 PDF with working links. Filename: `First_Last_Resume.pdf`. No ATS guarantee is made.
7. **AI API Usage** dashboard (`#/usage`):
   - *Application-tracked usage*: every Claude request this app makes (timestamp, model, feature, input/output tokens as returned by Anthropic, status, duration, error category). No keys, prompts or resume content are logged. Missing token counts show as n/a.
   - *Anthropic-reported usage*: only when `AI_USAGE_API_ENABLED=true` with an Admin key, using `/v1/organizations/usage_report/messages` and `/v1/organizations/cost_report`. This is **organization-level** data, not specific to this app or key, and is never added to the application totals.
   - Cost is shown only if provider-reported. Remaining credit is shown only as a labelled estimate when `AI_CREDIT_TOTAL`, `AI_CREDIT_START` and provider cost data exist. Nothing is hardcoded or invented.

## API

`GET /api/health` · `GET /api/config/status` · `POST /api/ai/interview` · `POST /api/ai/generate-resume` · `POST /api/ai/improve-section` · `POST /api/ai/analyze-job` · `POST /api/ai/suggest-improvements` · `POST /api/resume/pdf` · `GET /api/usage/status|summary|details`

Errors use `{ "error": { "code", "message" } }`. Handled: missing/invalid key, billing, rate limits, timeouts, network failure, unsupported model, invalid request, empty/truncated/malformed output. Failed requests are **not** retried automatically (to avoid extra cost); the UI offers a manual Retry.

## Privacy and security

- API keys stay on the server and are never sent to the browser. `/api/config/status` only reports whether a key is configured.
- Drafts are saved only in this browser (`localStorage`). Settings has a "Clear all saved drafts" button. The text you send to the AI goes to Anthropic through this server.
- All user content is HTML-escaped when rendered; the PDF renderer runs with JavaScript disabled and all network requests blocked.
- Request size limits, rate limiting, timeouts and a restrictive CSP are enabled.
- **Before any public deployment** you must add real authentication/authorization. `USAGE_LOCALHOST_ONLY` is not sufficient protection, and resume data and usage history are otherwise unprotected.
